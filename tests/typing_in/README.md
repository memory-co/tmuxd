# typing_in — 往里敲,以及"敲进去"到底承诺了什么

## 这个场景在测什么

这是 tmuxd **唯一的写入动作**,所以它的每个边角都值得钉:

1. **`send()` 是字面量,一个字符都不解释。** `tmux send-keys` 不加 `-l` 时把参数当
   **键名**解析,于是发一句 `"Enter the code"`,里面的 `Enter` 变成回车键 ——
   这是 tmux 用户人人踩过一次的坑。tmuxd 把它挡在接口形状上:文本走 `send()`,
   按键走 `send_key()`,不给混着写的机会。这条用**那句原话**当用例。
2. **前导横杠不是选项。** `send("--help me")` 得原样进去,不能被 tmux 的参数解析吃掉
   (实现上靠 `--` 分隔符)。
3. **`send_key()` 收的是键名**,而且真的按下去了 —— 用 `C-c` 打断一个 `cat` 来证明,
   因为"字符看起来在屏幕上"和"按键真的被终端处理了"是两回事。
4. **返回只意味着"字符交给 tmux 了"。** 不是命令跑完了,更不是跑成功了 ——
   这一层不读终端,没有能力知道后续。发一条注定失败的命令,`send()` 照样正常返回。
5. **会话没了就抛 `NoSuchSession`**,而不是静默丢弃。

## 不在这测什么

- **打到了哪个会话** —— 在 [`exact_targeting/`](../exact_targeting/)。
- **为什么没有 `capture` / `run` 去验结果** —— 在 [`nothing_reads/`](../nothing_reads/)。
  这里为了断言"字符确实进去了",只好用 `tests/conftest.py` 的 `screen()`
  下到 tmux 那一层;**测试是唯一真正需要读屏幕的调用方**,这本身就是那条设计线的注脚。
- CLI 的 `send` / `keys` 两条命令 —— 在 [`cli_shell/`](../cli_shell/)。
