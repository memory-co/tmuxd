# installing —— `tmuxd install` 与 `~/.tmuxd.json`

设计:[works/07-install.md](../../docs/v1/works/07-install.md)

## 测什么

**这条命令是辅助,不是步骤** —— 所以第一组用例测的是**不跑它的时候一切照旧**:
没有 `~/.tmuxd.json`,查找顺序和以前一模一样,`Tmuxd()` 不会因为你没装过而抱怨。

剩下的都是它真的干活时的规矩:

1. **网络优先,自带兜底** —— 下载失败要**降级并说出来**,不能静悄悄,也不能直接炸;
2. **校验和不符就是不装** —— 没有 `--force`,文件不能留在磁盘上;
3. **1.7.4 及更早直接拒绝** —— 上游那时还没发 `SHA256SUMS`,验不了就不下;
4. **json 里永远只有两个键** —— 试图写 `port` 要报错,这是"库敢默认读它"的前提;
5. **失效的路径降级** —— 记的二进制没了,回退到 PATH 并 warn,**不是异常**;
6. **不碰 `~/.tmuxd.conf`** —— 那是人手写的 CLI 配置;
7. **幂等** —— 已经有能用的就什么都不做,除非 `--refresh`。

## 不在这测什么

- **三级查找本身**(显式 / PATH / 自带)—— 在 [`finding_ttyd`](../finding_ttyd/) 里,
  这边只测**新插进去的那一级**(json)和它失效时的行为;
- **真的去 GitHub 下东西** —— 用例不联网。下载那层用打桩的 `urlopen` 测,
  要验的是"**校验、降级、拒绝**"这三条决策,不是 HTTP 本身;
- **真的跑包管理器** —— 非 root 时只该打印命令,而"打印了什么"正是要断言的;
  真装一遍 tmux 不是测试该干的事。

## fixture 来源

- `conftest.py::isolated_toolchain_file`(autouse)—— 把 `TMUXD_JSON` 指到一个不存在的
  路径上,免得开发机上真实的那份掺进来;想测"有这个文件"的用例自己 `monkeypatch` 回去;
- `fake_ttyd()` / `fake_tmux()` —— 会报版本号的假二进制,和 `finding_ttyd` 一个路数。
